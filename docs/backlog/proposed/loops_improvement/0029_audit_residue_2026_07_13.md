## Findings held here (audit numbering)
- **#6 Legacy/raw-factory `max_iterations` silently overridden to 20**:
  `ensure_limits` materializes `_limits.max_iterations=20` when `_limits` is
  absent, and limits wins over the scratchpad-migrated flat value — so
  `runtime.start(vars={"max_iterations": 100})` runs capped at 20. Bites raw
  `create_*_workflow` users only (the façades set `_limits`). Fix shape: in
  `ensure_*_vars`, seed `_limits.max_iterations` from the scratchpad/flat
  value BEFORE the materialized default wins. MemAct also resets
  `current_iteration` on legacy resumes (reads limits only).
- **#7 Repeat-side-effect guard evidence gap**: a skipped cycle records
  tool_calls but no observations, so the NEXT identical batch's prev-cycle
  scan judges a partial view. Partially mooted by the P0 fix (results are
  now genuinely re-executed); the guard's skip-cycle bookkeeping still
  deserves a synthetic marker so skips don't count as "the previous tool
  cycle".
- **#9 ReactAgent dead knobs**: `plan_mode` written to `_runtime`, read by
  nothing; `max_tokens`/`max_history_messages` written into `_limits` then
  nuked by `init_node`. The exact accepted-and-ignored class 0013 removed
  from MemAct — but on the FLAGSHIP surface, so removal is semver-visible:
  fold into 0024 (dead-surface pruning, green-light gated).
- **#10 Sibling max_iterations terminal returns the raw last message as the
  answer** (often a tool observation; KeyError on content-less host-seeded
  messages; no final assistant message appended). ReAct's conclusion-call
  shape is the fix; parity investment — check the C5 ruling / 0021 first.
- **#12 MemAct compose spin on non-dict KG result**: a custom host handler
  returning a non-dict makes compose re-issue the identical MEMORY_KG_QUERY
  forever (idempotency replays it instantly; consumes no iteration budget).
  Cheap guard: present-but-non-dict = failed compose, continue to reason.
- **#14 Hook steering queues leak for runs that terminate by failure**
  (discard only fires from done/max_iterations). Memory-only rot on
  long-lived hosts; fix belongs in the loop_hooks contract wave with 0028.
- **#15 Unmarked truncation in CodeAct's small-budget path** (`keep < 200`
  drops the suffix entirely — violates the marked-truncation policy; ReAct's
  twin keeps a marker at any bound). Plus: explicit `max_iterations=0`
  delegate arg silently widens to `max(parent, 20)` while
  `resolve_max_iterations` clamps explicit 0 to 1 — inconsistent "explicit
  narrow never widens" handling across the two surfaces.
